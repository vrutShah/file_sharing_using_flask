  SECTION 1 — LIBRARIES USED (What they are and why we use them)

PYTHON STANDARD LIBRARIES (built-in, no install needed):
---------------------------------------------------------

  os        → Interact with the operating system.
              Used to: create folders, build file paths, get file sizes,
              split filenames into name + extension.
              Example: os.path.join("uploads", "file.pdf")
                       → gives "uploads/file.pdf" on any OS

  uuid      → Generate universally unique identifiers (UUIDs).
              Used to: create a random unique ID for every uploaded file
              so two files with the same name never overwrite each other.
              Example: uuid.uuid4().hex → "bdba8e9b69464126815a487cad8f4013"

  json      → Read and write JSON (JavaScript Object Notation) files.
              Used to: save and load metadata (filename, description, size)
              in a file called metadata.json.
              Example: json.dump(data, file) → writes dict to JSON file
                       json.load(file)       → reads JSON file into dict

  io        → Work with in-memory byte streams (like a virtual file).
              Used to: save the QR code image into memory (RAM) instead of
              writing it to disk, so we can convert it to Base64 directly.
              Example: io.BytesIO() → creates an in-memory binary buffer

  base64    → Encode binary data (like images) into text format.
              Used to: convert the QR code PNG image into a Base64 string
              so it can be embedded directly inside JSON and shown in HTML
              without saving a separate image file.
              Example: base64.b64encode(bytes).decode() → "iVBORw0KGgo..."

  socket    → Low-level network interface.
              Used to: detect the machine's local IP address automatically
              so the download link shows the correct network IP.
              Example: socket.socket(AF_INET, SOCK_DGRAM) → creates UDP socket

THIRD-PARTY LIBRARIES (installed via requirements.txt):
-------------------------------------------------------

  flask     → A lightweight web framework for Python.
              Used to: create the web server, define URL routes (/upload,
              /d/<id>, etc.), render HTML templates, and return JSON responses.
              Key parts we use:
                Flask          → creates the app instance
                request        → reads incoming data (uploaded file, form fields)
                render_template→ loads and returns an HTML file from /templates/
                send_from_directory → sends a file as a download attachment
                jsonify        → converts a Python dict to a JSON HTTP response
                abort          → returns error pages like 404 Not Found

  werkzeug  → A utility library that Flask uses internally.
              We use one specific function:
                secure_filename → cleans up filenames to remove dangerous
                characters like "../../../etc/passwd" (path traversal attacks).
              Example: secure_filename("../../evil.exe") → "evil.exe"

  qrcode    → Generates QR code images from text/URLs.
              Used to: turn the download URL into a scannable QR image.
              Key settings:
                version         → size of QR (1 = smallest, 40 = largest)
                error_correction→ how much damage the QR can take and still scan
                                  ERROR_CORRECT_H = up to 30% can be damaged
                box_size        → how many pixels each QR square takes
                border          → white border around the QR in squares

  Pillow    → Python Imaging Library. qrcode uses it to create the PNG image.
              We don't call Pillow directly — qrcode uses it in the background
              when we call qr.make_image().

LINES 59-67: get_local_ip() FUNCTION
--------------------------------------

  LOGIC:
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    → Creates a UDP socket.
      AF_INET = use IPv4 addressing
      SOCK_DGRAM = UDP protocol (connectionless — no actual data is sent)

    s.connect(("8.8.8.8", 80))
    → Pretends to connect to Google's DNS server (8.8.8.8).
      No data is actually sent — UDP doesn't need a real connection.
      This trick makes the OS choose the right network interface and
      fills in our local IP as the source address.

    ip = s.getsockname()[0]
    → getsockname() returns (local_ip, local_port) as a tuple.
      [0] picks just the IP: "192.168.1.9"

    s.close()
    → Close the socket to free resources.

    return ip
    → Returns the local IP like "192.168.1.9"

  except Exception:
      return "127.0.0.1"
    → If anything goes wrong (no network, etc.), fall back to localhost.


LINES 70-82: make_qr_b64() FUNCTION
-------------------------------------

  LOGIC:
    qr = qrcode.QRCode(
        version=1,                              → smallest QR size, auto-grows
        error_correction=ERROR_CORRECT_H,       → 30% damage tolerance
        box_size=8,                             → 8 pixels per QR module/square
        border=3,                               → 3-module white border
    )

    qr.add_data(url)    → feeds the URL string into the QR encoder
    qr.make(fit=True)   → fit=True auto-selects the version (size) needed
                          to fit the data if version=1 is too small

    img = qr.make_image(fill_color="#0a0a0f", back_color="#f0f4ff")
    → Creates a PIL Image object (a PNG in memory)
    → fill_color = color of the dark QR squares (near-black)
    → back_color = background color (light blue-white)

    buf = io.BytesIO()
    → Creates an empty in-memory binary buffer (like a virtual file)

    img.save(buf, format="PNG")
    → Saves the PNG image into the buffer (not to disk)

    return base64.b64encode(buf.getvalue()).decode()
    → buf.getvalue() → gets all the PNG bytes from the buffer
    → base64.b64encode(...) → encodes bytes to Base64 bytes
    → .decode() → converts Base64 bytes to a UTF-8 string
    → Result: a long string like "iVBORw0KGgoAAAAN..."
      This string can be embedded in HTML as: <img src="data:image/png;base64,...">


LINES 85-90: human_size() FUNCTION
------------------------------------

  LOGIC:
    for unit in ("B", "KB", "MB", "GB"):
        if n < 1024:
            return f"{n:.1f} {unit}"   → e.g. "45.3 KB"
        n /= 1024                       → divide by 1024 and try next unit
    return f"{n:.1f} TB"               → fallback for huge files

  Example: human_size(1536) →
    1536 < 1024? No → n = 1536/1024 = 1.5
    1.5 < 1024? Yes → return "1.5 KB"

================================================================================
  SECTION 5 — GITHUB PUSH PROBLEM: WHAT WENT WRONG & HOW WE FIXED IT
================================================================================

THE PROBLEM:
------------

  When you first pushed the project to GitHub, you got these errors:

    error: RPC failed; curl 55 Send failure: Connection was reset
    fatal: the remote end hung up unexpectedly

  And then:

    error: RPC failed; HTTP 408 curl 22 The requested URL returned error: 408

  There were THREE separate problems happening at the same time:

  -----------------------------------------------------------------------
  PROBLEM 1: The uploads/ folder was included in the Git repository
  -----------------------------------------------------------------------

  When you ran "git add ." the first time (before creating .gitignore),
  Git tracked everything — including the PDF file you had uploaded during
  testing inside the uploads/ folder.

  That one PDF file was 21 MB. GitHub has a recommended limit of 50MB per
  file and a hard limit on push sizes. Trying to push 21 MB of binary data
  over a slow connection caused Git to:
    - Take too long (triggering the 408 timeout from GitHub's server)
    - Get the TCP connection reset mid-transfer (curl error 55)

  THE FIX: Create a .gitignore file before ever doing git add.
  .gitignore tells Git to completely ignore listed files/folders.

    echo uploads/ > .gitignore        → ignores the entire uploads folder
    echo metadata.json >> .gitignore  → ignores runtime-generated metadata

  But the file was ALREADY tracked by Git (from the first push attempt).
  Simply adding .gitignore doesn't un-track files Git already knows about.
  You have to explicitly remove them from Git's index (staging area):

    git rm -r --cached uploads/
    git rm --cached metadata.json

  --cached means: remove from Git tracking but KEEP the actual files
  on your hard drive. Without --cached, it would delete the files too.

  -----------------------------------------------------------------------
  PROBLEM 2: Git's HTTP buffer was too small
  -----------------------------------------------------------------------

  Git has a default limit on how much data it buffers when communicating
  over HTTP. With a 21 MB file, this buffer was being exceeded, causing
  the connection to drop mid-transfer.

  THE FIX:
    git config http.postBuffer 157286400
    → Sets the buffer to 150 MB (157,286,400 bytes).
    → 157,286,400 = 150 × 1024 × 1024

  -----------------------------------------------------------------------
  PROBLEM 3: "remote origin already exists" error
  -----------------------------------------------------------------------

  You ran "git remote add origin <url>" twice.
  The second time, Git complained because you can't add the same remote name twice.

  This was HARMLESS — the remote was already set correctly from the first time.
  You could have safely ignored this error message.

  If you ever need to change the remote URL, use:
    git remote set-url origin <new-url>   (instead of git remote add)

  -----------------------------------------------------------------------
  THE FINAL SUCCESSFUL PUSH — READING THE OUTPUT:
  -----------------------------------------------------------------------

    Enumerating objects: 16, done.
    → Git found 16 objects (files/commits) to push.

    Compressing objects: 100% (13/13), done.
    → Git compressed the files to reduce transfer size.

    Writing objects: 100% (16/16), 21.22 MiB | 17.05 MiB/s, done.
    → Still 21 MB because the PDF was in the Git HISTORY from the first push.
    → Even though we removed it with git rm --cached, the old commit
      still contained the file. Git pushes full history.

    * [new branch]      main -> main
    → SUCCESS! The branch was created on GitHub for the first time.

  -----------------------------------------------------------------------
  BONUS FIX: Remove the PDF from Git history permanently
  -----------------------------------------------------------------------

  Even after the successful push, the 21 MB PDF still lives in your
  repository's history. Anyone who clones it will download that PDF.

  To permanently erase it from all history:

    git filter-branch --force --index-filter \
    "git rm --cached --ignore-unmatch uploads/bdba8e9b69464126815a487cad8f4013.pdf" \
    --prune-empty --tag-name-filter cat -- --all

    git push origin main --force

  --force is required because you are rewriting history. After this,
  the repo will be clean and lightweight.

  -----------------------------------------------------------------------
  THE LF/CRLF WARNING
  -----------------------------------------------------------------------

    warning: in the working copy of '.gitignore', LF will be replaced by CRLF

  LF (Line Feed \n)   = Unix/Linux/Mac line endings
  CRLF (Carriage Return + Line Feed \r\n) = Windows line endings

  Git on Windows automatically converts LF to CRLF when checking out files
  and converts back to LF when committing, to keep the repo cross-platform.

  This is NOT an error — just a heads up. The file will work fine.

  To silence this warning permanently:
    git config --global core.autocrlf true


================================================================================
  SUMMARY — HOW THE WHOLE APP FLOWS
================================================================================

  1. User opens http://192.168.1.9:5000 in browser
     → Flask serves index.html via the "/" route

  2. User drops a file and types a description, clicks "Share File"
     → JavaScript creates FormData with the file + description
     → XHR sends a POST request to /upload
     → Progress bar updates via xhr.upload progress events

  3. Flask receives the upload:
     → Sanitizes filename with secure_filename
     → Saves file to uploads/ with a UUID filename
     → Saves metadata (original name, description, size) to metadata.json
     → Gets the local IP, builds the download URL
     → Generates a QR code image, encodes it as Base64
     → Returns all this info as JSON

  4. JavaScript receives the JSON response:
     → Fills in the result card (filename, size, description)
     → Sets the download link
     → Embeds the QR code as an inline Base64 image
     → Smooth-scrolls to show the result

  5. Recipient on another device scans the QR code or visits the link
     → Their browser hits /d/<file_id>
     → Flask looks up the file_id in metadata.json
     → Renders download.html with file info, QR code, download button

  6. Recipient clicks "Download"
     → Browser hits /d/<file_id>/file
     → Flask calls send_from_directory with as_attachment=True
     → File downloads with the original filename
